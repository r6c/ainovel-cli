# 细纲—正文重合检测边界

本文件是 AB5 的输入与误报基线。它不是运行时规则，也不是正文质量判决。

## 1. 可比较输入

同章可比较数据来自：

```text
OutlineEntry.Title
OutlineEntry.CoreEvent
OutlineEntry.Hook
OutlineEntry.Scenes[]
ChapterRecord.Content
```

配对键是章节号：

```text
OutlineEntry.Chapter == ChapterRecord.Chapter
```

只能比较同一章节。没有对应章节的大纲或正文时，不生成重合结论。

不使用 `outline.md` 作为原始比较输入，因为它包含 Markdown 标记、字段名、章节编号和人类可读装饰；运行时应使用结构化 `OutlineEntry` 字段。

## 2. 误报边界

以下内容即使在细纲和正文中重复，也不能单凭重复判定为照搬：

| 类别 | 示例 | 处理 |
|---|---|---|
| 章节标题 | “北侧冷阱” | 豁免；标题本来需要对应章节 |
| 人物/组织/地点 | “苏弦”“栖潮站” | 豁免或降权；专名是事实锚点 |
| 固定台词 | 章节合同要求出现的关键一句 | 豁免；可能是用户明确要求的锚句 |
| 系统提示 | “氧气剩余十二分钟” | 豁免或降权；格式化事实可能应逐字保留 |
| 任务清单 | “确认铜钥匙、进入冷阱、找到中继器” | 不单凭重合判定；是场景职责的正常展开 |
| 事实短语 | “前往北侧冷阱寻找中继器” | 仅作为事实一致性，不作为照搬证据 |
| 有意复述 | 角色回忆、前情提示、主题回环 | 交给 Editor 判断叙事功能 |

## 3. 真正候选

只有同时满足以下条件，才有理由进入未来 advisory：

1. 存在同章 `OutlineEntry` 与 `ChapterRecord`；
2. 重合文本超过明确的最小 Unicode 字符长度；
3. 不是标题、专名、系统提示、固定台词或必要任务事实；
4. 重合位于大纲的叙述性说明，而不是结构字段名称；
5. 正文没有增加人物、信息、动作、情绪或节奏功能；
6. 结果只作为证据交给 Editor，不自动改写或阻断提交。

“连续 15 字”只作为待验证候选阈值，不是当前产品规则。中文网文中的专名、事实短语和动作目标可能天然造成较长连续重合，必须先验证误报率。

## 4. 来源边界

```text
generated
→ 可以产生 advisory，仍由 Editor 判断

imported
→ 保留用户原文；不能因 advisory 清洗或阻断

user
→ 保留用户修改；如需重建事实，走 Revision
```

当前不把检测接入 Commit，也不让 Import/Revision 共享一个会改变正文的后处理器。

## 5. 当前 Go / No-Go

当前结论：**No-Go，暂不实现运行时照搬检测。**

原因：

- 同章输入已经可得；
- 但当前没有足够的标注样本证明 15 字阈值误报可控；
- 现有 `rules.Lint` 接口只接受正文文本，直接扩展参数会改变公共边界；
- 把大纲文本注入 Lint 可能让规则与 ChapterContract、Editor 责任重叠；
- 先做 advisory 仍需确定豁免和证据格式，不能用一个简单的字符串重合替代语义判断。

只有在新增自有样本、人工金标和误报统计支持下，才考虑一个独立的 `outline_copy` advisory。即使实现，也不直接阻断 Commit，不修改 imported/user 原文，不复制外部 JavaScript。
