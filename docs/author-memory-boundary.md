# 作者记忆边界设计

本文件定义“跨项目作者记忆”与现有 `UserRules`、Book Facts、Run Intent 的边界。

本阶段只做设计与可验证决策，不引入作者记忆存储、CLI、TUI、Normalizer 字段或新的事实源。

## 1. 结论

当前项目暂不实现独立作者记忆运行时。

现有全局 rules 已能满足一部分跨书复用需求：

```text
~/.ainovel/rules/*.md
→ 当前项目归一化
→ meta/user_rules.json
→ novel_context
```

但它缺少以下能力：

- 用户明确表达“记住”的语义边界；
- 单条记忆的确认回执；
- 冲突替代记录；
- 单条撤回/清除；
- 跨项目记忆的来源和审计历史。

因此作者记忆是一个真实的产品候选，但暂不满足“现在必须实现”的条件。先保留设计，等待明确的跨项目使用场景和交互需求。

## 2. 四类数据边界

| 数据类别 | 作用域 | 事实内容 | 当前事实源 | 是否可被作者记忆覆盖 |
|---|---|---|---|---|
| `UserRules` | 本书 | 当前书可执行的写作规则和稳定参数 | `meta/user_rules.json` | 只能通过本书规则更新，不由作者记忆静默覆盖 |
| Author Memory | 跨项目 | 用户明确要求长期记住的作者偏好 | 当前未实现 | 不能覆盖本书硬约束 |
| Book Facts | 本书 | 书中人物、时间线、伏笔、Knowledge 等事实 | `ChapterRecord.Facts` 及其投影 | 不可覆盖 |
| Run Intent | 单次运行 | 本次 Prompt、规划级别、推进模式和章节许可 | `meta/run.json` | 不可覆盖 |

补充：全局 rules 是跨书复用的输入来源，但每本书仍生成自己的 `UserRules` 快照；它不等于作者记忆。

## 3. 写入规则

未来若实现 Author Memory，只有同时满足以下条件才允许写入：

1. 用户明确使用“记住/以后都记住/跨项目保留”等长期意图；
2. 内容属于作者偏好、工作习惯或默认选择，而不是某本书的剧情事实；
3. 系统向用户回显拟保存内容；
4. 用户明确确认；
5. 写入结果带有稳定 ID、来源和时间；
6. 写入失败必须显式反馈，不能假装已记住。

以下内容禁止自动写入：

- 模型从正文推断出的作者性格；
- 某本书的角色、设定、伏笔或剧情真相；
- 本次运行的临时要求；
- Provider、API Key、路径、账号等敏感信息；
- 未经确认的文风归纳；
- “用户可能喜欢……”之类模型猜测。

## 4. 与 UserRules 的转换

作者记忆不能直接进入 Writer Context。未来正确方向应是：

```text
Author Memory
→ 用户选择/确认适用于当前书
→ 转换为 UserRules Candidate
→ 现有 BuildSnapshot/OverlaySnapshot 确定性合并
→ meta/user_rules.json
```

因此：

- Author Memory 是跨项目候选输入，不是运行时硬规则；
- `UserRules` 仍是本书唯一可执行规则快照；
- 当前书的 project rule、启动要求和硬门禁优先级高于作者记忆；
- 作者记忆不能直接改变 `ChapterFacts`、`RunMeta` 或 `Progress`。

## 5. 优先级

未来转换为本书规则时，建议采用：

```text
系统硬约束
→ 本书事实与本书硬规则
→ 当前运行明确要求
→ 本书 UserRules
→ 用户确认采用的 Author Memory
→ 普通自然语言参考
```

作者记忆不得覆盖：

- 已接纳正文事实；
- Chapter Contract；
- Knowledge/Foreshadow 生命周期约束；
- imported/user 正文来源权限；
- PendingCommit 恢复协议；
- 当前运行的明确反向要求。

## 6. 最小生命周期（仅设计）

如果未来进入实现，第一版只需要：

```text
用户提出“记住 X”
→ 解析为待确认候选
→ 回显候选内容和作用域
→ 用户确认
→ 写入一条记忆事件
→ 生成确认回执
→ 查询时按相关性和上限选择
→ 用户可撤回/清除该条记忆
```

建议以追加事件为审计记录、以投影为读取视图，但这只是未来设计方向；本阶段不创建文件格式。

最小字段候选：

```text
id
content
scope = author
source
created_at
updated_at
status = active / revoked
```

第一版不加入：

- 向量数据库；
- 自动语义合并；
- 置信度；
- 复杂冲突图；
- 多用户权限；
- 自动从所有对话学习；
- 作者画像评分。

## 7. 确定性决策矩阵

| 输入示例 | 处理 | 原因 |
|---|---|---|
| “以后每章约 1200 字” | 当前书 `UserRules` candidate | 是可执行的本书规则 |
| “记住我偏好冷峻克制的叙述” | Author Memory 待确认 | 明确跨项目作者偏好候选 |
| “这本书主角怕水” | Book Facts | 属于本书人物事实，不是作者记忆 |
| “本次先写到第 5 章” | Run Intent | 只影响本次运行 |
| “记住这本书的反派叫沈砚” | 拒绝作为 Author Memory | 书籍事实应留在本书 |
| “我可能喜欢短章节” | 不写入 | 没有明确记忆意图和确认 |
| “不要再使用这个设定” | 先判断作用域 | 可能是本书规则、运行要求或撤回记忆，不能猜 |
| “忘掉我之前关于比喻的偏好” | 待确认撤回 | 必须定位具体记忆，不模糊清空全部规则 |

## 8. 查询边界

未来注入当前书前，Author Memory 必须经过：

- 当前书适用性确认；
- 与本书 UserRules 的冲突检查；
- 相关性筛选；
- 固定数量上限；
- 不包含 Book Facts 或 Run Intent；
- 不直接注入未经转换的自由文本集合。

查询失败时应降级为“不注入作者记忆”，不能阻断本书已有创作事实；写入/撤回失败则必须显式反馈。

## 9. Go / No-Go

当前决定：**No-Go，暂不实现独立 Author Memory。**

理由：

- 现有全局 rules 已覆盖跨书复用的主要路径；
- 当前没有明确的用户交互入口和“记住”请求样本；
- 独立存储会增加第二套偏好事实源；
- 立即实现会迫使 UserRules、Author Memory、Style Profile 之间产生优先级协议；
- 当前发布版本不需要该能力才能完成核心创作流程。

未来进入实现的条件：

1. 出现可复现的跨项目偏好需求；
2. 用户明确需要单条确认和撤回，而全局 rules 不足以满足；
3. 先完成与 UserRules 的转换协议测试；
4. 先证明不会覆盖本书硬规则和 Book Facts；
5. 设计单独的隐私/迁移/删除策略。

## 10. 许可证边界

本设计只吸收抽象概念：明确记住、确认、回执、撤回、相关性上限和优先级。

不复制：

- `oh-story-claudecode` 的目录结构；
- `chinese-novelist-skill` 的 Skill 文本或模板；
- 任意外部代码、Prompt 或长文档。
