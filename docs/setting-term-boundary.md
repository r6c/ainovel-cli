# 设定术语边界评估

本文件是 AB6 的输入与误报基线，不是新的术语事实源，也不是运行时规则。

## 1. 当前可复用的事实

当前项目已有三类相关数据：

```text
WorldRule
→ 世界规则/设定约束

CastEntry
→ 有名字的次要角色首次出现与最近出现

KnowledgeEntry
→ 作者 Truth、角色 KnownBy、ReaderRevealedAt、Belief
```

它们的职责不同：

- `WorldRule` 描述世界如何运作，不记录术语首次出现；
- `CastEntry` 只记录配角名册，不是术语词典；
- `KnowledgeEntry` 记录认知事实，不应承载所有普通名词。

当前没有稳定的：

```text
术语 ID
术语首现章
术语类别
首次可感知线索
计划揭示章
```

因此不能把这些字段假定为已经存在，也不能从普通字符串出现自动推导完整术语生命周期。

## 2. 可评估输入

如果未来做术语首现 advisory，最小输入应来自已有接纳事实：

```text
ChapterRecord.Content
ChapterRecord.Facts
ChapterRecord.Chapter
OutlineEntry
WorldRule（仅作为已登记设定的参考）
KnowledgeEntry（仅作为读者/角色认知边界参考）
```

候选术语不能直接来自全部字符串 token。至少需要一个明确来源，例如：

- Writer/Architect 显式声明的新设定名词；
- `WorldRule` 中已有的稳定名称；
- 用户确认的术语清单；
- 人工标注的评测输入。

没有显式来源时，不生成“缺少术语解释”的高置信结论。

## 3. 误报边界

以下内容不应单凭首次出现就报警：

| 类别 | 原因 |
|---|---|
| 人名、组织名、地名 | 属于角色/世界事实，首次出现可能有意保持悬念 |
| 普通物件名 | 不需要每个名词都提供定义 |
| 视角角色熟悉的术语 | 角色无需对自己已知的日常概念解释 |
| 对话中的口语、绰号 | 解释不足可能是人物关系或语气功能 |
| 战斗/任务中的动作名 | 正文节奏不应被术语说明打断 |
| 系统提示和界面字段 | 可能需要保持固定格式，不应自动改写 |
| 读者已通过前文获知的术语 | 不应重复要求首次解释 |
| 故意延迟揭示的秘密名词 | 缺少完整定义可能正是悬念设计 |

## 4. 候选 advisory 的最低条件

只有同时满足以下条件，才适合生成低置信 advisory：

1. 术语来源明确，不是从全文 token 猜测；
2. 术语在本书中确实被当作新概念使用；
3. 当前章是该术语的首次有效读者接触；
4. 术语承担后续理解所需的事实或规则；
5. 当前文本没有提供类别、感官线索、功能线索或角色反应；
6. 前文没有通过 `ReaderRevealedAt` 或明确摘要提供同一信息；
7. 证据只指向章节和术语，不复制大段正文；
8. 结果只交给 Editor/Diagnostics，不自动修改正文或提交。

## 5. 与 Knowledge/ReaderKnown 的边界

术语首次出现不等于作者 Truth：

```text
术语出现
≠ establish
```

术语被角色说出不等于角色确认真相：

```text
角色提到术语
≠ learn
```

读者能够根据线索猜到不等于明确揭示：

```text
读者可推测
≠ reveal_to_reader
```

术语缺少解释也不等于认知越权：

```text
解释不足
≠ ReaderKnown/CharacterKnown 违规
```

任何未来实现都必须继续复用现有 Knowledge 的明确动作，而不能创建一套隐式的认知推导。

## 6. 当前 Go / No-Go

当前结论：**No-Go，暂不实现运行时设定词典或术语首现 advisory。**

理由：

- 没有稳定术语来源和术语 ID；
- 从正文自动发现术语的误报率尚未评估；
- `WorldRule`、`CastEntry` 和 `KnowledgeEntry` 不能直接互相替代；
- 术语解释质量依赖题材、视角和叙事意图，不能由字符串规则单独裁决；
- 新增术语事实源会与现有 Knowledge/WorldRule 产生重叠；
- 当前没有用户明确要求术语词典或可编辑术语工作台。

如果后续要继续，先建立人工标注的自有术语样本，并把输出限制为低置信 advisory；不新增平行状态机，不阻断 Commit，不清洗 imported/user 原文。
