## 可支持的方向性结论

运行时聚合记录支持以下有限判断：

- calibrated 的整体 recall 高于 baseline；
- `learn` 的召回和精确率均有改善；
- `establish` 的新增样本精确率和召回高于 baseline 聚合；
- `reveal_to_reader` 召回保持，但精确率下降，说明新增多动作说明可能使模型过度触发 reader reveal；
- `believe` 没有显示出精度改善；
- 负例结果不能简单概括为全为空，新增聚合记录仍有少量非空输出。

这些是方向性观察，不是可从仓库当前文件独立重算的逐样本证明。

理由：扩展聚合仍显示召回提升与精确率代价并存；没有一个同时改善所有动作的清晰 Prompt 方向。继续修改前，应先让真实评测直接使用已提交的可断点 Runner，并保留逐样本脱敏工件或可验证摘要。

- 本轮一次性协调器直接调用了 Import 结构化协议，但没有直接调用已提交的 `ImportKnowledgeRunner`。
- 结果工件未接入运行时 `UsageTracker`，Usage 为零值占位，不代表零成本。
- 逐样本结果已清理，因此新增 72 条调用的费用和 Token 不可从当前仓库工件追溯。
- Runner 本身的断点、Prompt 身份和原子落盘行为已由离线 fake 测试验证，但本次真实运行未验证该接入。

## 后续建议

如果继续此评测，应先补一个只使用已提交 Runner 的真实执行入口，并满足：

1. 每条结果立即原子落盘；
2. 结果至少保留 `round/sample/arm/action_signature`；
3. 结果记录真实 Usage 或明确标记 unavailable；
4. 统计脚本从保留工件重新计算 exact-match、顺序和混淆矩阵；
5. Provider 阻塞时可以从中断位置续跑。
